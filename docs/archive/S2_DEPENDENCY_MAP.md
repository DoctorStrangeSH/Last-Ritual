## Текущее устройство

Главная сцена `scenes/main.tscn` использует `scripts/main.gd` (около 2193 строк). В одном `Node2D` находятся игровые состояния, обработка ввода, экономика, логика боёв, сохранения и большая процедура `_draw()`. Из-за общего изменяемого состояния нельзя переносить несколько крупных функций за один раз.

## Минимальный безопасный порядок S2

1. **Проверить контракт** `reward_name`, `reward_detail`, `reward_note`: чистые функции по ID награды, не требуют доступа к объектам или сохранениям. Это первый кандидат для вынесения в `scripts/reward_catalog.gd` с `static func`.
2. Добавить тест, который сравнивает возвращаемые текстовые значения и IDs до/после для всех пяти типов даров. UI должен продолжать пользоваться существующими методами через тонкие обёртки либо прямые вызовы.
3. В одном PR вынести только каталог даров, без изменения баланса, интерфейса или JSON.
4. После зелёного CI и сохранения поведения исследовать аудио или отдельную валидацию JSON как следующий кандидат — но **не** рефакторить `_input`, `_draw` и боевой цикл одновременно.
5. Дальнейший вынос выбирать по фактической связности, а не количеству строк.

## Инварианты для любого рефакторинга

- Сохранения текущего формата version=1 должны читаться; постоянные meta-сохранения и тесты остаются изолированными.
- Цикл: пять дней/ночей → rewards/ritual → final_siege → win/lose; меню и клики по башням не меняются.
- Текущая экономика, цены, урон, эффекты и кулдауны без изменений.
- Запуск CI: Godot 4.4.1 headless import, `tests/campaign_smoke.gd`, экспорт Windows EXE.
- Отдельная ручная проверка визуала не подменяется CI.
