# Foozle BuilderPack — импорт и техническая карта

Источник: `Foozle_2DS0021_Spire_BuilderPack.zip`, переданный владельцем проекта.
Лицензия пакета: CC0 1.0 (см. исходный `Readme.txt`; копия должна храниться в `assets/spire/licenses/Foozle_BuilderPack_Readme.txt`).

## Извлечение исходников

Запустить из корня проекта:

```bash
python tools/import_foozle_builderpack.py /path/to/Foozle_2DS0021_Spire_BuilderPack.zip
```

Скрипт проверяет ZIP CRC, сигнатуры PNG и извлекает исходные файлы без перекодирования:
- `Tower_Construction.png` — 1152×1536 RGBA (58 945 байт в предоставленном архиве).
- `Tower_Collapse.png` — 3328×192 RGBA (13 465 байт).
- `Wisp_Animations.png` — 576×384 RGBA (12 335 байт).

## Точная геометрия исходных листов

Проверены оригинальные PNG непосредственно из ZIP (ZIP CRC проходит):

| Лист | Размер | Сетка геометрических ячеек | Всего ячеек |
|---|---:|---:|---:|
| Tower Construction | 1152×1536 | 6×8 по 192×192 | 48 |
| Tower Collapse | 3328×192 | 26×1 по 128×192 | 26 |
| Wisp Animations | 576×384 | 9×6 по 64×64 | 54 |

Это точные размеры сетки, вычисленные по исходным размерам и визуально размеченные в contact sheet. Они **не доказывают**, что все ячейки — кадры одной последовательности: в Construction заметны несколько блоков с готовыми башнями и строительными частицами. Порядок, группировка и FPS остаются неподтверждёнными.

Для повторного анализа запустить:

```bash
python tools/analyze_foozle_builderpack.py /path/to/Foozle_2DS0021_Spire_BuilderPack.zip
```

Скрипт создаёт подписанные contact sheets и `frames.json` в `build/foozle_builderpack_preview/` (не игровые ресурсы и не коммитить автоматически).

## Важные ограничения

- Это оригинальные листы спрайтов, а не готовые Godot SpriteFrames.
- Для `Tower_Construction.png` визуально заметны несколько горизонтальных полос с разными вариантами башен и эффектами пыли. Нельзя объявлять равномерную сетку кадров, пока не сверены исходные PSD/описание пакета или точные границы кадров.
- `Tower_Collapse.png` — длинная горизонтальная последовательность обломков/пыли; границы кадров и FPS необходимо измерить/проверить по исходной раскладке.
- Не растягивать и не масштабировать исходники. Импортировать с nearest filtering, отключённым mipmaps и без потери альфа-канала.
- Сначала собрать тестовую сцену/превью SpriteFrames и подтвердить кадры визуально; затем подключать к строительству/продаже. Gameplay-состояние и экономика должны изменяться сразу, а анимация быть только визуальной.
- Wisp — отдельный анимированный строительный дух; не подключать как башню или врага без подтверждения роли в механике.
- Автоматический extraction tool проверяет целостность архива и PNG signature, но не проверяет Godot import и не заменяет визуальную QA.
