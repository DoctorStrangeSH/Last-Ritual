# Last Ritual — модульные исходники Алтаря душ

## Статус

Шесть новых **редактируемых исходных SVG** по пути `assets/spire/towers/necro/source/layers/`. В них нет текста или непрозрачного фона. Они являются **художественными кандидатами**, не заменяют утверждённый пользователем PNG-референс и ещё не подключены к runtime.

| Уровень | Основание | Оружие |
|---|---|---|
| 1 | `base_level_1.svg` | `weapon_level_1.svg` |
| 2 | `base_level_2.svg` | `weapon_level_2.svg` |
| 3 | `base_level_3.svg` | `weapon_level_3.svg` |

Одинаковые `viewBox="0 0 128 128"`, `shape-rendering="crispEdges"`, точки стыковки примерно `(64,90)`. Это дизайн-ориентир: точные pivots следует проверить в реальной сцене Godot.

### Почему слои раздельные
Основание и оружие могут импортироваться отдельно. В будущем это позволит анимировать оружие и показывать специализации без замены корпуса. **Пока не менять** `td_tower_visuals.gd`: runtime necro ещё использует временный `pulse`-арт.

### Прежде чем объявить готовым
- Сверить форму, цвет, детализацию с одобренными пользовательскими изображениями.
- Проверить действительную SVG-растеризацию и PNG-альфу.
- Перевести кандидаты в прозрачные PNG и при необходимости переписать/дорисовать детали под художественный стандарт.
- В Godot проверить компоновку base+weapon, якорь, вид на целевом масштабе, nearest и smoke tests.
- Подготовить специальные оверлеи «Жнец»/«Легион», снаряды и impact.
- Опубликовать оригинальный PNG-концепт v0.5 отдельно в Git с проверкой SHA-256.

**Зелёный CI не заменяет художественную приёмку.** Не выдавать эти SVG за готовые спрайты.


## Воспроизводимый PNG preview через Godot

Команда (Godot 4.4.1 из корня проекта):

```bash
godot --headless --path . --script res://tools/export_necro_layers.gd
```

Экспортирует **девять PNG-кандидатов** в локальный `build/art-preview/necro/`:
три base, три weapon и три собранных level. Это **generated preview**, не исходники. Исходные SVG в Git; их можно растрировать повторно. Экспорт проверяет размеры 128×128, наличие как прозрачных, так и видимых пикселей, затем повторно открывает PNG. Такой тест включён в GitHub Actions на PR-ветке.

**Не считать production-ready**: следует сопоставить внешний вид с утверждёнными пользователем детализированными изображениями и проверить pivot при отображении на игровой карте. Нельзя менять `td_tower_visuals.gd` до визуального QA и оригинального artwork export. Бинарный концепт v0.5 не входит в этот PR и должен быть загружен отдельно с неизменным SHA-256.


## Специализации (редактируемые кандидаты)

Добавлены `specialization_siege.svg` — «Жнец» (коса, светящиеся руны), и `specialization_swarm.svg` — «Легион» (штандарты и несколько призрачных душ). Оба файла совпадают по холсту с уровнями 1–3, применяются к собранному третьему уровню только для предпросмотра.

Экспортёр создаёт дополнительно `specialization_siege_level_3.png` и `specialization_swarm_level_3.png`, всего **11 candidate PNG**. Процесс не подключает эти изображения к игровому runtime. До художественной приёмки и проверки масштабов/эффектов статус остаётся *candidate*. Доступные исходные концепты и игровой баланс не изменяются.
